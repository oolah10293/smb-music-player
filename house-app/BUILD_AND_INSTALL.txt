HOUSE MUSIC v0.3.0 — BUILD AND INSTALL

Application: House Music
Application ID: com.housemusic.player
Version name/code: 0.3.0 / 5
Minimum Android: 8.0 (API 26)
Compile/target SDK: 36

INSTALL THE SUPPLIED APK

Install HouseMusic-v0.3.0.apk over the delivered v0.2.1, v0.2.0 or v0.1.1 APK. It uses the same
retained signing key, so the update preserves the server address, route sync
corrections and other app settings. Leave SMB Music installed.

If still using House Music v0.1.0, record the server address and route sync
corrections before uninstalling only House Music. Its CI signing key was not
retained, so it cannot update in place. Install v0.3.0, re-enter the server address
and use the gear for each route's -1000 to +1000 ms sync correction.

On first launch, enter the Pi's LAN host. On the Browser page, Server opens
the connection setting. Enter only the Pi hostname or IPv4 address. There
is no bundled deployment address.

No smb:// prefix, port, folder, SMB username or SMB password belongs in this
field. House Music uses HTTP 8787, MPD identity port 6600 and Snapcast 1704.
Install house-audio-server v0.10.0 or newer for Radio. Library indexing requires
v0.9.1 or newer. Last played requires server v0.11.0. No S3 update is needed.

Swipe left/right through Library, Now Playing and Radio.
On Radio, paste a direct HTTP(S) stream URL and tap Add & Play. The Pi saves and
names the station for all controllers. Tap a saved station to play it, hold it to
rename, or tap its X to remove the bookmark. Deleting the currently playing station
does not stop its audio. Undo restores the bookmark. For local music, return to
the library browser and choose a song or PLAY LIST.

Radio is live: Pause stops the stream and Play rejoins the current broadcast.
Seeking, Previous/Next, Shuffle, Repeat and queue sorting are unavailable for radio.
Bluetooth automation, manual mute and the sync gear retain their existing behavior.
Pull down on the browser file list to refresh its local music index.

BUILD FROM SOURCE

Open house-app as its own project in Android Studio. If using the source ZIP,
open its extracted root folder (the folder containing settings.gradle.kts). Requirements:

- Java 17 and Python 3
- Android Gradle Plugin 9.4.0 / Gradle 9.6.0
- Android SDK 36 / Build Tools 36.0.0
- Android NDK 28.2.13676358 (r28c)
- CMake 3.22.1

All commands below run from the house-app directory.

Linux/macOS:

    python3 native/prepare.py
    ./gradlew assembleDebug testDebugUnitTest
    ./gradlew lintDebug -PapiCompatibilityCheck

Windows:

    SETUP_GRADLE_WRAPPER.bat
    py -3 native/prepare.py
    gradlew.bat assembleDebug testDebugUnitTest
    gradlew.bat lintDebug -PapiCompatibilityCheck

The wrapper bootstrap downloads the official wrapper JAR and checks its pinned
SHA-256. Native preparation downloads checksum-pinned Snapcast, FLAC and Boost
sources. These generated sources are excluded from Git and included in the
matching CI source archive; preserve them when distributing the receiver.

See docs/RELEASE_0.3.0.md for build evidence, APK manifest identity, checksums and
signing information. Delivered APKs reuse the retained private debug signing key.
CI builds use their own debug key; do not distribute them as in-place upgrades
without signing with the retained key. Never include the private keystore in Git
or a source archive.

See docs/TESTING.md for physical acceptance. A successful build and API-26 lint
do not establish an S8/J3 hardware pass or verified audio synchronization.
